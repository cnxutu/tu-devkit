# Primary 仓库与任务范围语义

## 目标

消除 `tu-devkit` 作为 Primary 仓库时的两种职责混淆：它应始终提供公共运行时约束，但不应自动成为可读取、核实或修改的工程范围。

## 设计

`ai-guidance/AGENTS.md` 将明确区分：

- Primary（P0）是会话启动时优先读取的公共协作入口；用户无需在每个任务中重复提及 P0。
- P1、P2、P3、P4、K1、K2 等目标项目由用户任务识别，决定实际可读取、核实或修改的源码范围。
- 仅当会话首次任务显式包含 `P0` 时，P0 才加入实际任务范围；该范围在后续消息中延续，直至用户明确改变。

因此，“调整 P1 的 xxx 功能”应先应用 P0 公共约束，再读取并操作 P1 所需的局部约束和代码；不默认读取或修改 P0 的内容。

## 修改边界

仅修改 `ai-guidance/AGENTS.md` 的入口与会话范围说明。保持现有事实优先级不变：用户最新明确要求与目标仓库局部约束/代码优先于产品知识和 Core 通用规则。

## 验证

复读入口条款，确认以下三种场景无歧义：仅 P1、显式 P0 + P1、仅维护 P0。
